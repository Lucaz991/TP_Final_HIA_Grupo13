Defensa en capas

  1. Borde: Cloudflare termina TLS y publica hostnames por túnel. La app queda pública; el webhook de Mercado Pago se autentica por firma HMAC, no por JWT. Los paneles administrativos se protegen con la autenticación propia de cada servicio (decisión del grupo, sin Cloudflare Access).
  2. Frontend/Nginx: sirve Angular y actúa como proxy a `/api/`. En el laboratorio aplica una CSP local deliberadamente restrictiva.
  3. Backend/API: JWT para sesión, rol para funciones administrativas, propiedad/participación para recursos, validación de entradas, rate limit de login y firma HMAC del webhook.
  4. Datos: backend no habla directo con los nodos PostgreSQL; entra por HAProxy. Patroni + etcd administran el clúster y la replicación.
  5. Operación: Prometheus, exporters, Grafana, Alertmanager, GLPI, Nextcloud, n8n y backup forman el plano operativo. Todavía falta cerrar el circuito completo de incidente y restauración.

Mensaje para explicar al equipo

  1. Internet no entra directo al servidor: entra por Cloudflare y el túnel resuelve servicios internos.
  2. Los puertos Docker quedan en localhost; GLPI, Nextcloud, n8n y Grafana piden su propia cuenta.
  3. La API no confía en el frontend: cada request pasa por JWT, rol y propiedad del recurso.
  4. Los pagos no confían en el body: el webhook exige firma y el backend consulta el estado real del pago.
  5. La base no queda expuesta: el backend usa HAProxy y el clúster Patroni/etcd queda en una red separada.
  6. Las pruebas destructivas no tocan producción: H24 usa base, credenciales, volumen, puertos y adaptadores propios.

Importante: los resultados actuales demuestran controles en el laboratorio. No afirmar que producción está validada hasta repetir las pruebas después del despliegue.
